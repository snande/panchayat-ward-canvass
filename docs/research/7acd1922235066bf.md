# Initiative decisions that bear on the build

# 0005: polling-day tracking is a team-observed tally from outside the perimeter; the acceptance bar is reliability, not latency

Date: 2026-10-06. Status: accepted.

## Decision

Feature 2 records what the candidate's workers outside the 200 m line
observe and self-report, never anything sourced from inside the booth
during polling hours. The client accepts tens of minutes of latency on the
condition that the tally is reliable and robust. That condition is the
acceptance criterion: entries survive no signal (local store, sync later,
SMS fallback), two workers reporting the same voter do not double count,
and the tally reconciles against the official turnout at close.

# 0006: voter phone numbers come from the candidate's own door-to-door canvass, at least one per household, with consent noted; never from brokers

Date: 2026-10-06. Status: accepted.

## Decision

Phone numbers are not on the roll. The team collects them during the door
to door campaign, aiming for at least one number per household, entered
against the household in the app with a note that the voter agreed to be
contacted. The product never ingests purchased or broker-supplied number
lists. This is a design invariant, not a feature: it is what separates the
product from the enforcement cases in the legal report.

# 0012: the shell and the roll relay are served together from Cloudflare Pages; GitHub Pages is retired for this project

Date: 2026-10-07. Status: accepted (facilitator's decision on the client's
behalf; supersedes the hosting half of 0011, the public-repo half stands).

## Decision

The delivery repository stays public and deploys to Cloudflare Pages on
every push to its default branch. The static shell is served as before,
and the Engineer's roll relay (`relay/rollRelay.mjs`, a fetch-handler
function) runs as a Pages Function on `/roll` of the same origin. The
custom domain `canvass.takshavid.com` is a CNAME at Porkbun to the Pages
project, so the domain's DNS does not move. GitHub Pages is switched off
for the repository once the Cloudflare deployment answers.

## Why

The commission's roll server sends no cross-origin header, so the app
fetches rolls through a same-origin relay (research of 2026-10-06, verdict
`relay-required`). GitHub Pages serves static files only, so the relay
path answered 404 and the first phone check of the download failed
(delivery issue #20). The relay was written against the standard
Request/Response API and runs unchanged as a Pages Function. Free tier,
no server to keep alive, no DNS migration, no change to the app or to the
Mandate's self-serve roll fetch.

## Rejected

- Mirroring ward PDFs into the repository: breaks the generic self-serve
  fetch (decision 0008) and done condition 1 of the Mandate.
- A Cloudflare Worker route on `canvass.takshavid.com`: needs the whole
  takshavid.com zone on Cloudflare, which moves the website and mail DNS
  for one path.
- An always-on host for `relay/server.mjs`: a monthly bill and an
  operations duty for kilobytes of traffic.

## Consequence

The same function is where a paid licence check belongs later: the shell
is public like any sign-in page, and the relay and the sync server are
where a candidate's key is enforced (stage 4).

# 0013: the coordinator's phone is the interim SMS recipient; a gateway number is a paid-product item

Date: 2026-10-07. Status: accepted.

## Decision

For the Rajasthan field test the "team number" that the polling-day tally
SMS is pre-filled to is the campaign coordinator's own mobile number. The
coordinator reads each arriving SMS and enters the tally in the app, which
is exactly how the Charter's Phase 3 acceptance is worded ("once that SMS
arrives at the client-provisioned gateway or coordinator number and is
entered"). No SMS gateway number is provisioned for the test.

The number is a per-team setting the coordinator enters in their own
installation, never a constant in the repository: the repository is
public, and each candidate's team has its own coordinator.

## Why

- Zero cost and zero lead time; the first poll is 24 October.
- Inbound SMS to a phone needs no telecom registration; the worker sends
  an ordinary person-to-person SMS from their own phone.
- A gateway with automatic import (an Indian virtual long code from a
  bulk-SMS provider, or a dedicated Android phone running an open-source
  SMS-gateway app that posts received messages to the sync server) saves
  the coordinator the typing. That is worth doing only once a team's
  volume justifies it, which is a stage-4 decision for the paid product.

## Consequence

The Phase 3 "SMS tally fallback" deliverable needs a coordinator-side
"enter SMS tally" entry point and a per-team number setting, not an
inbound webhook. The automatic-import variant stays open as an option
behind the same entry point.

# 0014: the v2 Mandate targets the remaining Rajasthan panch and sarpanch polls; samiti and zila parishad members, licences and ads come later

Date: 2026-10-09. Status: accepted (the client's answers to the v2 draft's open questions).

## Decision

1. The second never-stop Mandate for `panchayat-ward-canvass` aims at
   the remaining Rajasthan panch and sarpanch polls (24 Oct, 30 Oct,
   5 Nov, 16 Nov 2026), provided the build finishes within a few days.
   Its `target_date` is 17 Oct 2026.
2. Panchayat samiti and zila parishad members are a later phase.
3. EPIC numbers are stored, encrypted with the team's other data, so
   search can find a voter by EPIC. Version 1 dropped them under its
   minimal-data constraint; they are printed on the public roll.
4. Click-to-WhatsApp ads stay out: Meta's advertiser authorisation
   (experiment 0004) has not been started, and its lead time is longer
   than the window.
5. Team data is not deleted on a fixed 30-day clock. After the result
   the candidate chooses to keep or delete; kept data lives only while a
   licence or test term runs. The exact period waits for the legal read
   before the DPDP retention rules apply on 13 May 2027.
6. Licences, payment and the seller's console are a later phase; the
   v2 Mandate uses activation codes the operator issues. Pricing is
   researched in `research/2026-10-09-licence-pricing.md`.

## Why

The delivery review (`workstreams/never-stop-delivery-review-2026-10-09.md`)
showed version 1 is not yet field-ready; the friends' polls are the only
test available before 2027, so the build that serves them comes first and
the selling features follow.

## Consequence

The v2 dossier holds sixteen done conditions ordered so polling day is
safe even if the last phases slip. Which phase each friend's panchayat
votes in must be confirmed before intake; a team whose poll is 24 Oct has
about a week with the finished app.
